# fetcher —— FactSet 抓取脚本

Author: Xuhao Chao · License: MIT

## 首次安装(只做一次)

在 **fetcher/ 目录下**执行:

```
npm install                      装 playwright 和 xlsx
npx playwright install chrome    让 playwright 认到本机 Chrome
npm run login                    弹出浏览器,手动登录 FactSet 一次,登完关窗口即可
```

登录状态会保存下来,之后不用再登。

日常抓取默认采用 `FS_HEADLESS=auto`：先在后台启动 Chrome；登录仍有效时全程不显示窗口。
如果检测到登录已失效，脚本会先关闭后台浏览器（释放同一个持久化 profile），再打开可见
Chrome 等你登录，完成后自动继续。`npm run login` / `--login` 始终打开可见窗口。

需要固定行为时可设置环境变量：`FS_HEADLESS=0` 始终显示 Chrome；`FS_HEADLESS=1` 始终后台运行。
强制后台时若登录失效，脚本会停止并提示先运行 `npm run login`，不会在后台无限等待一个无法完成的登录。

## 日常使用

```
npm run fetch        跑一轮抓取(每家公司 8 步:估值 / 价格 / 走势 / 目标价 / 空头 / 新闻 / 期权 / 汇总)
npm run selftest     纯函数自检,不开浏览器、不碰网络(条数以命令自己打印的为准,当前约 298 项)
```

Windows 上更省事的做法是直接双击**仓库根目录**的 `run-factset.bat`——它会自己 `cd` 进来,
依赖缺失或与 `package-lock.json` 不一致时才会用 `npm ci` 修复，Chrome 不在标准安装位置时才会安装。
命令行参数照传(`run-factset.bat --login`)。

macOS 可双击仓库根目录的 `run-factset.command`，首次登录可在 Terminal 运行
`./run-factset.command --login`。启动器会检查 Node、依赖和 Google Chrome；数据仍只写入本机 `Assets/`。

需要在同一天强制刷新新版期权字段时，可临时设置 `FS_FORCE_OPTIONS=1`；它只绕过期权文件的新鲜度判断，其它数据仍按原周期运行。

拉取结束后默认**不自动打开仪表盘**，避免定时任务或连续补数据时不断弹窗口。确实希望完成后打开时，
先设置环境变量 `FS_OPEN_DASHBOARD=1`；未设置、设为 `0` 或其它文字都保持关闭。

入口只有根目录这一个。`fetcher/` 下曾经也有一个同名 bat,已经退役——两个入口迟早会
各自漂移,到时候"我明明跑了"和"脚本明明没跑"就同时成立。

启动后和每轮拉取结束后都回到同一个一级菜单。`run` 明确开始一轮，
`exit` 明确退出；空回车只会留在菜单，不再在“首轮开始 / 完成后退出”之间变含义。
其他命令：增删 ticker、`edit` 改清单、`mkt` 管理市场序列、`sync` 清单对齐、`chk` 体检、
`bt` 回测、`sources` 看台账、`open` / `dashboard` / `仪表盘` 打开 Dashboard。打开后确认看到页面，
按回车会回到同一菜单。无 TTY 的定时任务不进交互菜单，仍自动单轮后退出。

## 清单与 Assets 的对齐(每次启动自动跑一遍)

`tickers.txt` 决定拉什么,`Assets/` 决定仪表盘显示什么——**这是两回事**,因为仪表盘扫的是文件夹,
不是清单。所以曾经出现过这种情况:`Assets/` 里有 6 家公司的数据,`tickers.txt` 只写了 2 家,
于是另外 4 家每轮都被跳过,数据停在几周前,但屏幕上它们照样在。缺数据你会去查,旧数据你只会照着做判断。

现在启动时会先对一遍,并且**直接把"有数据却没登记"的代码补进 `tickers.txt`**,同时告诉你补了谁、
它们手上有哪几类数据、缺哪几类。反过来"清单里有但一个文件都没有"的只报告不删——
那可能是你刚加进去还没拉,也可能是拉失败了,哪种都不该由脚本替你决定。

补错了直接在菜单里输 `-代码` 删掉。删除会在 `tickers.txt` 里留一行 `# ignore: 代码`:
**删清单并不删数据**,没有这行的话它下次启动就会被盘上的旧文件补回来。想恢复就删掉那行 ignore,
或者在控制台里直接把代码再输一遍。

也可以在仓库根目录用 `npm run fetch` / `npm run test:fetch`,效果相同。

## 文件都落在哪

**数据全部写进仓库根目录的 `Assets/`**(不是 `fetcher/Assets/`),按类型分子目录:
`estimates/` · `charting/` · `targets/` · `news/` · `options/` · `summary/` · `misc/`,
台账与跑批日志在 `Assets/_logs/`。归类只看**文件名**,与仪表盘的识别规则是同一套,
所以以后想换布局也不用动摄取代码。

**配置留在 `fetcher/` 下**:`tickers.txt` · `markets.txt` · `.options-url`。

每次启动会先做一次幂等的目录迁移(`lib/migrate.mjs`),把旧版本散在
`fetcher/Assets/`、`fetcher/lib/` 或 `Assets/` 根下的文件搬回正确位置;同名冲突保留较新的那份。

## 抓取失败时看哪里

台账在 `Assets/_logs/sources.txt`:一行一个产出文件,记录状态、FactSet 标签路径、URL、
最近成功/失败时间,以及失败时**具体卡在哪一环节**(导航 → 等待页面 → 切换 Report Type →
定位表格 → 解析行 → 写文件)。

同目录下还有 `fetch-YYYY-MM-DD.log`,是当天控制台输出的完整副本——终端滚动缓冲区
总是刚好把关键那几行吃掉,所以直接看文件。

失败环节直接对应代码文件:`steps/` 下有同名文件,打开那一个就行,不用通读全脚本。
完整的文件对照表见 [`../docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md)。

### 空头持仓那一步会自己交证据

Ownership 面板是异步渲染的,所以这一步**等到解析成功为止(最多 45 秒)**,而不是固定睡 8 秒
——只等文字出现会稳定地拿到一个数字还没填上的空面板。

失败信息分两种,对应的下一步完全不同:

- 「45 秒内页面上没出现 Short Interest 面板」——多半是没登录,或者这只标的本来就没有这项数据
- 「面板在,但读不出 %流通盘」——这才是真改版。此时日志里会**摘出页面上那一段原文**,
  照着它改 `steps/short-interest.mjs` 顶部的正则即可,不用再开一次浏览器复现

回补天数和占流通盘是**分开读**的:只读到一个就先记一个,缺的那一格在 csv 里留空
(仪表盘按空值跳过,不会显示成 0)。

还有第三种失败,而且它是这里最要紧的一种:**「读出来了但不对劲」**。
正则匹配上了、台账写着成功、数字却来自隔壁那一格——2026-07-29 那一轮就是这样,
七只标的全部"成功",占流通盘写着 68.7%、80.7%、76%、72.1%(那其实是机构持股)。
失败会报警,错的数字不会:它会一路走进走向概率面板,让每只大盘股常年吃一记空头扣分,
你在屏幕上看不出任何异样。

识破它不需要看页面,两个数字自己就矛盾:
`占流通盘% ÷ 回补天数 =(空头/流通盘)÷(空头/日均量)= 日均成交量占流通盘的百分比`。
68.7 ÷ 1.6 ≈ 43,即"每天换手 43% 的流通盘",量级上不可能。
所以这一步卡的是这个比值(`SI_MAX_TURNOVER = 20`)和绝对上限(`SI_MAX_PCT = 50`),
都在 `steps/short-interest.mjs` 顶部。不自洽就连同页面原文一起判失败——
**宁可这一格空着,也不能拿错的数去打分。**

而根因也不在正则,在**取数的范围**。Ownership 面板上三个统计块是并排的:

```
SHORT INTEREST   2.5 DAYS / 1.4% FLOAT
FLOAT            96.2%
INST. OWNERSHIP  72.1% OF FLOAT
```

整个 frame 的 `innerText` 把三块拼成一段,于是 `%\s*of\s*Float` 越过空头那一格,
一路匹配到机构持股的 72.1 —— 正则没写错,它只是被喂了不该看见的文本。
现在改成先用 `lib/browser.mjs` 的 `frameBlockContaining('SHORT INTEREST')`
**爬到 DOM 里那一格**(最小的、文本里含数字的祖先)再解析:隔壁的数字在**结构上**就够不着了。
排版可以改,"数字和它的标题在同一个盒子里"不会改,这比再补几条更精细的正则牢靠。
万一那一格爬不出来,退回整页文本时会先用 `siBlockTooWide()` 数百分号——
一段里出现两个以上 `%` 说明范围又太宽了,此时宁可失败也不猜。

自检里这几条断言用的是**实地抄回来的原文**(`SHORT INTEREST 2.5 DAYS / 1.4% FLOAT`,
大写、没有 `of`),不是想象中的写法;还有一条反向断言直接把三块拼在一起,
钉住"必须读回 1.4 而不是 72.1"。断言写得像页面而不像正则,才能挡住下一次。

### 期权那一步单独说一下:走接口,不走那张表格

**这一步的主路是直接调 FactSet 前端自己用的两个接口,不用手动导出,也不用刮屏。**
导出和刮屏都还在,但已经降级成兜底。

为什么不看那张表格:Options Montage 的表格是**虚拟滚动**的,DOM 里永远只有视口内那二十来行,
而少读**不会失败**——它会安安静静写出一份看着挺正常的 `Options.csv`,
然后压力位面板拿着这份残缺的链一本正经地算错 max pain 和 OI 墙。
和空头持仓那一次是同一类错:**读到了不等于读全了。** 导出能读全,但要你伸一次手。
接口两样都不占。

#### 两个接口(2026-07-30 实地记录,细节抄在 `lib/fql.mjs` 顶部)

都在 `my.apps.factset.com` 同源下,用现成的登录态(`credentials:'include'`)就能调:

```
GET  /services/IDCServ/oc?symbol=<代码>              期权链目录
POST /services/Fql?app=html_reports&string_na=1      按合约代码取值
     body: symbols=<逗号分隔>&exprs=<表达式>
```

第一个回竖线分隔的纯文本,25 列,第 0 行表头。**每行结尾多一根竖线**,
解析必须 `.split('|').slice(0,-1)`,否则凭空多一列。里面有两条腿的合约代码、行权价、
到期日、是否调整过、标的代码——**唯独没有未平仓量**,它是目录不是数据。

第二个按合约代码取未平仓量,返回扁平 JSON,每项 `{$error,$expression,$symbol,$value:[[数]]}`。
实测可用的标识符:`P_OPT_OPEN_INTEREST` · `P_OPT_STRIKE_PRICE` · `P_OPT_EXP_DATE` ·
`P_OPT_VOLUME` · `P_OPT_DELTA` · `P_OPT_BID_PRICE` · `P_OPT_ASK_PRICE` · `P_PRICE`。
账号或合约不给可选字段时保留为空，并在日志中报告覆盖率，不影响核心 OI 快照落盘。

**吞吐实测:** NVDA 目录 1947 行,筛完 626 条腿一个请求 2.8 秒全回,零报错。
**导出那条路"一次最多 500 个合约"的上限在这里不存在。**

#### 这条路唯一要提防的:200 不等于拿到了

代码写错、或者这只标的压根没有期权,接口回的是 **HTTP 200 加一个空 body**,不是 404。
所以 `parseOptionChainTable('')` 明确判失败,不许它变成"成功但零行"。
日志里看到「期权链目录是空的」就是这个情况,先核代码。

丢弃合约的每种理由都单独计数:已过期 / 超过 90 天 / 离现价超过 ±35% / 调整过的合约 /
标的对不上。日志里看得见丢了什么,而不是只看见剩了多少。

没取到未平仓量的腿**超过 20% 整份拒收**,然后往下试导出——
缺一块的链算出来的 max pain 是错的,宁可这一轮不写。

#### 兜底一:手动导出的点法(实测走通)

1. 打开 Options Montage,输入代码
2. 行权价那个下拉 → **Custom Strikes** → **% from At-the-Money** 填 **25** → OK
   (这个 25 不是随便填的:仪表盘那边的 `OPT_WINDOW` 就是 ±25%,两边对齐)
3. 选一个月份页签
4. 右上角工具图标 → **Download**

**一次最多 500 个合约**(合约数 = 行权价数 × 2)。超了会弹
*"More than 500 contracts to download as per selected filters."* ——
注意它是**一个文件都不给**,不是给你一份截断的。所以标的一大就得**按月份分几次下**,
下下来的几份脚本会自己拼成一条链(同一个"到期日+行权价"以 `asof` 最新的那份为准)。

#### 脚本怎么收这些文件

启动时按顺序扫这几个目录里所有 `optionsMontage_*.xlsx`:

```
%FS_OPT_INBOX%  →  fetcher/options-inbox/  →  ~/Downloads
```

不用改名、不用整理,下载完放着就行。

**sheet 名就是这份文件的身份证。** 导出的 sheet 名形如 `NVDA-USA_20260728`,
代码、交易所、快照日期全在里面。脚本拿它做三件事:认这份文件是谁的、取快照日期
(而不是拿"今天"冒充)、以及**对不上就整份拒收**——下载目录里什么都有,
混一条别人家的链进去比没有数据危险得多。逐行还会再核一次 `Root Symbol`
(调整过的合约根符号带后缀,所以是前缀匹配)。超过 45 天的旧导出会被点名跳过,
日志里写清楚跳了哪份、为什么跳,而不是静默丢掉。

到期日是**精确到天**的,不再是"某月第三个周五"那种猜法——周度期权早就把这个假设废了。

#### 兜底二:刮屏

接口没成、导出也一份都找不到时才会去刮屏,并且这一轮的日志里一定会打一条显眼的 ⚠,
外加上面那份点法清单。**看到那条 ⚠ 就当这一轮的期权轨不可信**,补一次导出再跑。

刮屏那条路径本身的注意事项照旧:期权链**不在 Company 里面**——它是和 Company 平级的
**顶层页签**(与 Charting 同级),不带公司上下文,所以脚本落地后要自己往搜索框里输代码。
实测地址是 `https://my.apps.factset.com/workstation/options-montage/`。
**输代码在前,读表在后**:同一个会话里页面很可能还停在上一只股票的链上,
先读就会拿到一张完整、合理、但属于别人的表。

地址按这个优先级找:环境变量 `FS_OPT_URL` → 上一轮记住的 `fetcher/.options-url` →
几个候选 slug 逐个试 → 最后回首页点顶层 Options 页签现场探测(探测结果写进 `.options-url`,
这个代价只付一次)。都不行就把浏览器地址栏里的地址直接给它:

```
set FS_OPT_URL=https://my.apps.factset.com/workstation/<那一段>/{ticker}
```

`{ticker}` 是占位符,会被换成实际代码;贴一个带具体代码的完整地址也认。
也可以不设环境变量,直接把这一行写进 `fetcher/.options-url`。

`Assets/` 里的 FactSet 导出是授权数据,已在 `.gitignore` 排除,不要提交到公开仓库。
