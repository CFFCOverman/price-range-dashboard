## 根因与修正

| 问题 | 证据及影响 | 本次处理 |
|---|---|---|
| 页面身份检查太早 | 只等第六行表格出现就读身份；表格与身份异步渲染。GOOGL/SPCX/META 两次导航都未通过。是否仅为渲染慢仍需在线验证 | 每次导航后最多轮询身份 15 秒，再决定重导航；保持错误证券禁止写入 |
| 默认停在 FY2 时错记台账 | 原逻辑固定包在 FY1 的 step 中，却按实际财年保存文件；AMD/AVGO FY2 成功无法清除 FY2 旧失败 | 先确认财年，再用实际 FY1/FY2 登记与保存 |
| 初始化失败伪装成 FY2 标签重试失败 | FY1 导航失败后，FY2 仍报“标签重试 3 次为空”，实际上未走该读取过程 | 两份估值都记录共同初始化失败，不编造后续重试 |
| 标签为空猜 FY1 | 可能把页面保留的 FY2 写入 FY1 | 标签不明或不是 FY1/FY2 时拒绝估值写入 |
| ASML P/E 校验失败报“写文件” | 日志显示 0/61 个有效正 P/E；这不是磁盘写入故障 | 保留隔离与原文件，失败阶段改为解析行并保留校验原因；不能据此断言 FactSet 本来没有 P/E |
| 汇总混入历史失败 | 汇总扫描整个 ledger，包含本轮未尝试产出 | 用本轮尝试集合筛选最终失败；历史台账继续保留供体检 |
| 失败后被新鲜度跳过 | 仅根据旧文件修改时间判断 | 台账为 FAIL 的产出不按文件较新跳过 |
| 周频导出当作日线 | 只检查至少 13 个收盘价和总跨度，未检查日期间隔 | 对下载候选去重日期，检查中位间隔不超过 3 天且至少 13 点；不通过则保留候选、不覆盖原文件、报失败 |
| 期权失败不计入最终缺项 | 结果矩阵有期权列，misses 却漏掉它 | 缺项统计纳入期权 |

## 模块职责与数据保护

- `fetcher/lib/round.mjs`：每轮重置尝试集合，编排公司及市场任务；输出本轮结果。进度 100% 表示任务走完，不代表全部成功。
- `fetcher/lib/ledger.mjs`：按产出文件保存最近状态和时间。本轮失败明细不含现价这种未单独登记的字段，因此与矩阵缺项数不必相等。
- `fetcher/steps/ticker.mjs`：证券页面初始化、财年识别、切换和实际财年台账绑定。
- `fetcher/steps/estimates.mjs`：身份检查、估值校验、一次重拉、异常隔离。身份仍依据估值 iframe 文本，若新版页面不显示代码，需补充真实页面诊断，不能放宽到仅相信导航 URL。
- `fetcher/steps/charting.mjs`：下载候选先校验价格与频率，再替换正式文件。频率门槛是保守的异常检测，不是交易日完整性认证。
- `fetcher/lib/companies.mjs`：新鲜度与现价合并；companies.csv 行数可能包含历史公司，并非本轮更新成功数。

估值隔离在 `Assets/_logs/rejected-estimates/`，成功覆盖前备份在 `Assets/_logs/last-good-estimates/`。不合格 Charting 候选留在对应正式文件名后加 `.pending.xlsx`，仅供排查。不要手动改名为正式日线。
