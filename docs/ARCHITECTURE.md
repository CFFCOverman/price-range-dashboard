# 目录结构与模块划分 · Architecture

Author: Xuhao Chao · License: MIT

这份文档回答一个问题:**想改某个功能,该打开哪个文件。**

## 一句话说清这个仓库

仪表盘的**交付物必须是零依赖单文件 HTML**(要能直接双击打开、要能挂 GitHub Pages),
但 2500 行挤在一个文件里没法维护。所以这里的做法是:源码按功能域拆在 `src/` 下分模块开发,
`tools/build.mjs` 把它们按 `src/manifest.json` 的顺序原样拼回单文件产物。
拼接不做任何打包、转译或改写——**产物与拆分前的单文件逐字节相同**,这是这次重构唯一可信的验收证据。

代价只有一条:**改完 `src/` 要跑一次 `npm run build`**。忘了跑不会静默出错——
`npm test` 的第 [0] 组断言会先比对产物与 `src/` 是否同步,不同步直接红。

### `Assets/` 的分层

```
Assets/{estimates,charting,targets,news,options,summary,misc}/   数据,按类型
Assets/_logs/sources.txt                                          源出台账
Assets/_logs/fetch-YYYY-MM-DD.log                                 每天一份跑批日志
Assets/_logs/backtest-history.csv                                 回测台账(长表,一行一个指标)
```

分子目录是**免费的**:仪表盘的 `ingest/folder.js` 递归到三层深,且靠**文件名**判断数据类型,
不看它在哪个目录里。所以布局怎么改都不用动摄取代码。

写盘只有一个入口:`config.mjs` 的 `assetPath(文件名)`——归类规则表 `ASSET_RULES` 就在它旁边。
**任何地方都不要再自己 `path.join(OUT_DIR, ...)`**,那是上一版把文件写丢的原因。

#### 哪些文件覆盖写,哪些追加写

不是"能留就留",而是看这份文件**自己带不带历史**:

| 文件 | 写法 | 为什么 |
|---|---|---|
| `{代码} Options.csv` | **按 `asof` 追加**,保留 365 天 | 每次导出只有"此刻这条链"。不叠层,昨天那堵 OI 墙后来顶没顶住就永远查不了(v16.8 起) |
| `{代码} News.csv` | 追加 | 同上,标题是一条条冒出来的 |
| `short-interest.csv` | 按日期追加 | 同上 |
| `companies.csv` | 覆盖 | 是当期快照汇总,不是历史 |
| charting / estimates / targets 的 `.xlsx` | **覆盖** | 每份导出**内部就带着**整段历史(日线一年、估值月度 ~44 个月)。留旧版只会让 `folder.js` 重复导入 |

追加的那几个都是**追加进同一个文件**,不是按日期建子目录。原因在上面那段:
`ingest/folder.js` 的 `collectDirFiles` 往下钻三层且**不看目录名**,
任何 `Assets/options/2026-07-30/` 这样的目录都会被整个吞进去、和当期文件一起导入两遍。

## `src/` —— 按功能域划分

改一个功能只碰一个目录,这是划分边界时唯一的取舍标准。

| 目录 | 负责什么 |
|---|---|
| `src/index.html` | 外壳:head、页面结构、两个占位符(`/*@build:styles*/`、`/*@build:scripts*/`) |
| `src/styles/` | `base` 变量与主题 · `overview` 总览表 · `detail` 明细与情景矩阵 · `pressure` 压力位 · `charts` 图表 |
| `src/js/core/` | `utils` 通用工具与 SVG 助手 · `csv` CSV 解析 · `state` 全局状态 · `i18n` 中英词条与 `t()` |
| `src/js/ingest/` | 数据摄取:每种输入文件一个模块(companies / estimates / snapshot / charting / targets / signals(空头·新闻·期权)/ price-summary),外加 `resolve` 文件归属判定、`files` 顺序导入、`folder` 文件夹连接与记忆 |
| `src/js/valuation/` | `calc` 估值区间核心(P/E 分位、EPS 情景清洗、`calcRange`) · `volstats` 波动率统计 |
| `src/js/pressure/` | 压力位三轨:`technical` 筹码分布 · `options` 期权 OI 墙(按窗口内 OI 选到期日,不按日历远近) · `confluence` 三轨合流与打分 |
| `src/js/direction/` | `scores` 走向概率的六维信号与市场级自动信号 |
| `src/js/render/` | 渲染层:`overview` · `detail` · `pressure` · `direction` |
| `src/js/app/` | `render-root` 总渲染入口 · `events` 事件绑定与启动(**唯一有顶层可执行语句的地方**,必须排在最后) |

### 三条不能破的约束

**产物只能有一个 `<script>`,而且不能是 IIFE、不能是 `type=module`。**
`tests/test-app.mjs` 用 `page.evaluate` 直接调用顶层的 `calcRange` / `pressureLevels` / `state`,
一旦包进闭包或模块作用域,整套断言全部够不着。`tools/build.mjs` 里有对应的护栏检查。

这条约束往回倒推,就成了对 `src/js/**` 每一个文件的写法要求:**只许有顶层 `function` 声明和顶层 `const`**。
不许 `import` / `export`(那会逼出 `type=module`),不许 `(function(){…})()` 包一层(那会把符号关起来),
也不许在模块里写"顺手初始化一下"的裸语句。这看起来像洁癖,其实是拼接模型的直接后果:
十几个文件被原样首尾相接成一个脚本,谁在自己文件里做了什么,别人是看不见的 ——
唯一还能靠得住的,只有"一个文件 = 一堆声明"这条纪律。

**`src/manifest.json` 的顺序就是执行顺序,而且这个顺序带着语义。**
拼接之后 JS 引擎按两套规则处理这些声明,它们的行为完全不同:
**顶层 `function` 声明会提升**,所以函数之间怎么互相调用都无所谓,`engine.js` 里的函数可以放心调
排在它后面的 `render/*.js` 里的函数;但**顶层 `const` 是按脚本顺序逐个求值的**,
在求值到它那一行之前处于 TDZ,读它不是 `undefined` 而是直接 `ReferenceError`。
于是判据只有一条:**一个 const 的初值里读到的另一个 const,必须排在它前面。**
`src/js/sim/engine.js` 的 `SIM_PRESETS` 读 `PX_HORIZONS`,所以 `sim/*` 必须排在 `pressure/params.js`
之后;`pressure/params.js` 反过来被要求"每个值必须是字面量、不许由别的 const 派生",
就是为了让它没有前置依赖、可以安全地排在最前。`tools/backtest.mjs` 的沙箱装载清单里
抄了同一份顺序,并在注释里钉了一句"必须与 manifest 的 21–25 一致" —— 两处顺序不一致,
坏的是回测,而且坏法是 TDZ 抛错,至少会当场炸。

**`src/js/app/events.js` 必须排在 manifest 最后**,这条比上面那条更硬。
它是全仓库唯一一个有顶层可执行语句的文件:第一行就是 `const drop = $('drop')`,
接着一路 `$('fileInput').addEventListener(...)` 地绑下去。这意味着两件事。
一是它读的每一个符号都必须已经求值完毕 —— 它绑的回调里引用的函数可以靠提升,
但 `$()` 本身是 `core/utils.js` 里的东西,拼在它前面才行。
二是**它没有任何容错**:`$()` 就是 `document.getElementById()`,元素不存在就返回 `null`,
下一句 `.addEventListener` 立刻抛 `TypeError`,而这是一个顶层未捕获异常 ——
**整个 `<script>` 从抛出点开始全部不再执行**。页面不会白屏、不会弹错,
它会渲染出一个静静躺在那里、点什么都没反应的仪表盘。所以新面板的 DOM 必须
**静态写死在 `src/index.html` 里**,不许在 JS 里 `createElement` 出来再绑:
后者一旦哪个 id 拼错,代价不是这个面板坏了,是这个面板后面所有面板一起坏了,
而且坏得毫无声音。加新模块时插进 manifest 的合适位置,`events.js` 后面永远不许再加东西。

### 压力位引擎:两个同名不同义的陷阱

这一域里所有"位置"都以同一把尺子度量:**`1u = σd · √h · P`**。
σd 是日对数收益标准差,h 是持有期天数,P 是现价。带宽、合并距离、视野闸门全部写成 u 的倍数,
好处是同一组常数在波动率不同的票、持有期不同的档上都还成立;
坏处是这把尺子的两个输入各自都有一个同名的兄弟,喂错了不抛错。

**第一个是 σ 的量纲。** `volStats(ticker).sigma` 是**年化**的(乘过 `√252`),
`sigmaD().sd` 是**日**的,两者差 √252 ≈ 15.87 倍。它们都是有限正数、都叫 sigma,
所以把年化那个喂进引擎不会有任何一处报错 —— 只会让 u 放大约 16 倍,
于是每条带的 edge 都趋近 0、触及概率齐刷刷显示 99%、可靠性图整个贴在右边界,
而 Brier skill 只是变成一个不大不小的负数,读起来像"这个持有期上模型就是不行",
不像 bug。这是本仓库最像 v17.1 那次"财年配错"的一处静默事故,所以配了三道防线:
`params.js` 顶部那段注释(讲清换算)、`[7]` 组那条 `sigmaD × √252 ≈ volStats.sigma` 的比值断言(挡回归)、
以及 `reachProb()` 里 `if (sd > 0.25) return NaN` 的运行期哨兵(日波动率 25% 的股票不存在,
真喂错了就当场变成"算不出"而不是"算出个漂亮数")。

**第二个是 horizon 这个词。** `state.horizon` 是**财年**,取值 `'fy1'` / `'fy2'`,
归估值那一侧;压力位面板的**持有期**是另一个字段 `state.plHold`,取值 `'short'|'mid'|'long'`,
映射到 h = 5 / 21 / 63;买入模拟面板还有第三个 `state.simPref.hold`。
`state.js` 里那两行注释("绝不能喂给 `pressureLevels` 的第四参"/ "与 horizon 是两回事")
不是提醒,是事故记录。喂错的后果链条完整走一遍是这样的:`PX_HORIZONS['fy1']` 是 `undefined`,
`√undefined` 是 `NaN`,带宽 NaN,所有位置被过滤光,两个数组都空,
渲染层看见空数组就 `sec.hidden = true` —— **面板整块消失,控制台一个字都没有。**
消失比出错数字安全,但它同时也意味着这类 bug 只能靠断言发现,不能靠肉眼。

### 财年判定:只信数据自己带的标签

一份 Estimate History 到底跟的是第几个财年,`src/js/ingest/estimates.js` 读的是表里
`Estimate History` 那一行右边的财年末标签(`FactSet Estimate History Jan '27E | …`),
拿它和这批数据最新一行的日期比,差满几个整年就是第几个财年。**文件名只在读不到标签时兜底。**

这条顺序是反过来写过的,代价很大:v17.1 之前用的是 `/FY\s*2/i.test(fileName)`,
于是 `… FY3 Estimate History.xlsx` 被当成 FY1,Jan '29E 的 P/E 分位配上了 Jan '27E 的 EPS,
NVDA 的中枢从 +11.9% 翻成 −16.5%。文件名是 `fetcher/lib/browser.mjs` 贴的,记录的是"抓取时以为在哪个页签";
表里那行标签是 FactSet 写的,是数据本身。判定口径要挂在后者上。

判定出来之后,收什么有明确分工 —— 混口径是这一层唯一会造成"数字反号"的错误:

| | FY1 | FY2 | FY≥3 |
|---|---|---|---|
| EPS | ✓ 进 `fy1` 槽 | ✓ 进 `fy2` 槽 | ✗ 三年后的盈利乘不上明年的分位 |
| P/E 分位库 | ✓ 唯一来源 | ✗ | ✗ |
| 修正动量(上调/下调家数) | ✓ | ✗ | ✗ |
| 价格序列(`P/E × Mean`) | ✓ | ✓ | ✓ 还原的是同一支股票的股价,与财年无关 |

### 口径护栏:`P/E × EPS` 必须约等于现价

`src/js/valuation/calc.js` 的 `baseGap()`:分位库最新一点 × 基准 EPS,和现价差超过 **25%** 就在卡片上出红字。
这两个数原本摆在同一份 Estimate History 的同一行,乘回去就该是那天的股价。

阈值是量出来的:八份配对正确的真实文件偏差落在 −11.5% ~ +0.9%(快照日期差几天,加上 P/E 只有一位小数),
FY3 配 FY1 那次是 −40%。

两条约束不要改掉:**只报警不改数**(说不清是哪一边错时不该替人做主,自动"修正"成一个看起来合理的数比显示一个明显不合理的数更危险),
**红字必须进 DOM**(`src/js/render/detail.js` 的 `renderMatrix`)—— 护栏只在 console 响等于没响。

## `fetcher/` —— 一个抓取步骤一个文件

FactSet 页面改版时坏掉的一定是某一个具体步骤。所以这里按"抓取步骤"切,而不是按技术层次切:
台账 `Assets/_logs/sources.txt` 的"失败环节"列点名哪一步,照名字打开 `steps/` 下同名文件即可。

| 路径 | 负责什么 |
|---|---|
| `fetcher/factset-fetch.mjs` | CLI 入口:`--selftest` 短路、`--login`、轮次循环 |
| `fetcher/lib/config.mjs` | 路径锚点、Assets 归类规则、环境变量与全局开关(`FS_OUT` / `FS_NO_VOLUME`) |
| `fetcher/lib/migrate.mjs` | 启动时的幂等目录迁移:把旧版本放错位置的数据搬回来 |
| `fetcher/lib/options-url.mjs` | 期权顶层页签的地址解析、候选与记忆(仅刮屏兜底路径用) |
| `fetcher/lib/fql.mjs` | 期权走接口那条主路的**纯函数**:期权链目录解析、筛合约、切批、拼装、验收。一行网络代码都没有——解析错了自检会红,网络错了台账会红。顶部有两个端点的实地记录 |
| `fetcher/lib/log.mjs` | 进度条与带时间戳日志 |
| `fetcher/lib/ledger.mjs` | 源出台账 v2:登记产出、`step()` 包装、失败子阶段 |
| `fetcher/lib/browser.mjs` | 浏览器按需启动 + 跨 iframe 的通用抓取原语 |
| `fetcher/lib/tickers.mjs` · `markets.mjs` | 两份清单文件的读写与内存状态(含"忽略名单":你删掉的标的不会被数据复活) |
| `fetcher/lib/reconcile.mjs` | 清单与数据对齐:扫 `Assets/` 反推有谁 → 补进 `tickers.txt` → 报告缺谁、缺哪几类 |
| `fetcher/lib/selftest-env.mjs` | 只做一件事:`--selftest` 时把输出改到临时目录(必须是入口的**第一个** import) |
| `fetcher/lib/menu.mjs` | 控制台菜单(增删清单 / `edit` / `mkt` / `sync` / `chk` / `bt` / `sources`) |
| `fetcher/lib/registry.mjs` | 产出登记表:抓取与体检共用同一份元信息,永远不会对不上 |
| `fetcher/lib/health.mjs` | `chk` 体检:台账 × 文件真实修改时间交叉核对 |
| `fetcher/lib/companies.mjs` | `companies.csv` 增量维护与 20 小时新鲜度判定 |
| `fetcher/lib/round.mjs` | 一轮的编排(公司 × 8 步 + 市场序列) |
| `fetcher/lib/opt-store.mjs` | 期权链的合并与滚存(纯函数,不碰 fs):按 `asof\|到期日\|行权价` 去重、365 天滚掉、超限时按**整份最老快照**驱逐。拎出来就是为了让自检覆盖得到 |
| `fetcher/lib/backtest.mjs` | 回测的排期与调用:菜单 `bt` 手动跑、每自然月自动跑一轮。**只出报告,不改任何权重** |
| `fetcher/lib/roster.mjs` | 拉取清单落盘给仪表盘看(`Assets/summary/roster.csv`),以及落榜满一年的数据挪进 `_to_delete/`。判定按**代码成组**、清单为空时不动手 |
| `fetcher/lib/selftest.mjs` | 纯函数自检,不开浏览器(含路径锚点、Assets 归类、清单对齐、拉取清单与落榜清理、期权接口解析、滚存边界与回测排期断言;条数以命令自己打印的为准,当前约 298 项) |
| `fetcher/steps/*.mjs` | estimates / price / targets / short-interest / news / options / charting,外加 `ticker.mjs`(单公司 8 步编排) |

`lib/browser.mjs` 里的 `ctx` / `page` 是会被重新赋值的模块级绑定。ESM 的 import 是**活绑定**,
所以各 step 直接 `import { page }` 读到的永远是当前实例;但反过来**不允许跨模块给 import 绑定赋值**——
清单状态 `TICKERS` / `MARKETS` 因此配了 `setTickers()` / `setMarkets()`,菜单通过它们回写。
入口里主流程全部用动态 `import`,是为了让 `--selftest` 在创建 readline 之前就短路退出(否则无终端环境会挂住)。

### 路径锚点:拆模块时最容易踩的一个坑

`path.dirname(fileURLToPath(import.meta.url))` 的值**跟着文件走**。上一版把 `config.mjs`
从 `fetcher/` 挪进 `fetcher/lib/`,那个叫 `SCRIPT_DIR` 的锚点就悄悄深了一层——
于是数据写进了 `fetcher/Assets/`、台账写进了 `fetcher/lib/`,脚本一路"成功",
仪表盘却一个新文件都看不见。没有任何一处报错,因为每一步单看都是对的。

所以现在锚点按**它是哪一层**命名,并且不再有含糊的 `SCRIPT_DIR`:

```
LIB_DIR  = <repo>/fetcher/lib     ← import.meta.url 所在
FETCHER_DIR = <repo>/fetcher      ← 配置文件(tickers.txt / markets.txt / .options-url)
                                    与期权导出收件箱 options-inbox/
ROOT_DIR = <repo>                 ← Assets/ 与产物 html
```

`selftest` 里有五条断言直接钉住这三层的关系和 `Assets`/`_logs` 的位置——
再挪文件时,坏的是断言,不是你半个月后的数据。

### 清单与数据对齐:两个真相来源必须每次对一遍

`tickers.txt` 决定**拉什么**,`Assets/` 决定仪表盘**显示什么**——这是两个独立的真相来源,
而仪表盘扫的是文件夹、不是清单。所以一旦某个标的的数据在盘上、名字却不在清单里,
它照样出现在屏幕上,只是永远不再更新。**缺数据你会去查,旧数据你只会照着做判断**,后者危险得多。

`lib/reconcile.mjs` 在每次启动时(菜单之前)把两边对一遍:

- 判断依据是**文件名**,和 `registry.mjs` 的产出命名、仪表盘 `ingest/` 的识别规则同一套。
  不解析文件内容、不读 `companies.csv`——多一条独立口径就多一种两边说法不一致的可能
- **补齐是单向的**:Assets 有、清单没有 → 自动写进 `tickers.txt` 并当场报出补了谁。
  反过来清单有、Assets 没有,只报告不删——那可能是刚加进去还没拉,也可能是拉失败了
- **忽略名单**(`tickers.txt` 里的 `# ignore: XXX-US` 注释行):删清单并不删数据,
  所以没有这份名单的话,你手动删掉的标的下次启动就会被盘上的旧数据"复活"。
  一个东西删掉后自己长回来,比工具少干点活严重得多

菜单里输 `sync` 可以随时手动再对一次。

### 拉取清单:让仪表盘也知道"清单里有谁"

上面那一段解决的是"清单漏了谁",反方向那半边由 `lib/roster.mjs` 补上:**清单外的东西不该出现在屏幕上**。

每次启动(排在对齐之后,顺序不能反 —— 对齐会往清单里补人,先写就会写出一份少了他们的清单)
往 `Assets/summary/roster.csv` 写一份当前清单:公司写 `role=company`,市场级序列带自己的角色。
仪表盘的 `src/js/ingest/roster.js` 按表头 `ticker,role,active` 认出它,把清单外的公司**默认不画**,
表格底下留一行「另有 N 家不在拉取清单里,已隐藏」可以点开。数据照常载入,只是不画。

三条边界必须记住,因为它们失效时终端上一个字都不会报:

- **没有 `roster.csv` → 完全不过滤。** "没有清单"和"清单是空的"是两件事
- **清单和数据完全对不上 → 也不过滤。** 空表格看起来和 app 坏了一模一样
- **那个展开开关不参与任何计算。** 走向概率的默认同行只取清单内的公司,但看的是清单不是开关 ——
  否则点一下提示行,估值区间会跟着漂

`roster.csv` 末行是一句以 `#` 开头的说明。CSV 没有注释语法,那行会被解析成一行数据,
仪表盘靠"ticker 以 `#` 开头就跳过"滤掉它。两侧自检各钉了一条:改措辞可以,改掉那个 `#` 就凭空多一家公司。

### 落榜数据的清理:一年为界,挪不删

同一个文件里的第二件事。不在清单里、**且最后一次更新已过 `RETAIN_DAYS`(365)天**的,
整组挪进仓库根的 `_to_delete/`(复用 `migrate.mjs` 的 `retire()`),并打印挪了谁。最后的删除由人按。

一年这个界和期权链滚存(`opt-store.mjs`)是同一个 —— 两处不一致就没人说得清历史留多久。
判定用文件 mtime,不另存"删除日期":清单一删,那个代码就不再被抓,mtime 自然冻结在最后一次抓取那天,
它本身就是"凉了多久"。少一份状态,少一次两边对不上的机会。

四条护栏:清单为空时一个都不动(空清单多半是读失败,按字面办事会把 `Assets/` 搬空);
按**代码成组**判定,只要还有一个文件比一年新就整组留下(挪一半会留下一份自相矛盾的历史);
`markets.txt` 里的市场序列也算"还在用"(漏掉的话 SPY 的日线一年后会被当成落榜公司挪走,
而走向概率的基准轨会安静地空掉);读不到修改时间就留着,别猜。

### 回测:重叠样本是这里最容易骗到自己的地方

`npm test` 问的是"算得对不对",`npm run backtest` 问的是另一个问题:**这几条线过去准不准**。
两者不能互相替代,也不该混在一起——回测要读 `Assets/`(授权数据、不进仓库),
在没有数据的机器上它只会打印"读不到日线",不会红。所以它不进 `npm test`。

脚本里有一处必须留神:**滚动窗口的样本是重叠的**。h=63 时相邻两个观测共用 62 天走势,
它们不是两条独立证据。命中率照 n 算(那是最好的点估计),但标准误只能按 `effN = n/h` 算——
不折算,z 会凭空放大 √h ≈ 8 倍。第一版就栽在这上面:五条结论里有四条报了红,
折算之后全部回落到"看不出"。**一个纯噪声的结果被打扮成 z=-9,而它其实是 z=-1.2。**
所以 `zBinom()` 的 `effN` 是必传参数,每张表都有"独立"这一列——
写不出有效样本数的命中率,就不该出现在报告里。

反过来同样要防:`effN` 太小的时候也不许判"合格"。63 日那行 ±1σ 只有 49.6%(应 68.3%),
但 `effN=9`,判语是"样本太少,看不出"而不是绿灯——**没测出问题不等于没问题。**

新闻那一组(F)的 `effN` 分母是 `max(前瞻, 30)` 而不是前瞻:`newsScore` 的打分窗口本身有
30 天记忆,5 日前瞻下相邻两天读到的是同一批标题,按 `n/5` 算会把独立样本高估六倍。
**信号自己的记忆和前瞻期,哪个长按哪个折算。**

### 回测沙箱:词法 `const` 不挂 `globalThis`,漏一个就是静默的 `undefined`

`tools/backtest.mjs` 不重写算法 —— 重写出来的东西只能测"我理解得对不对"。
它用 `node:vm` 起一个假窗口,把 `src/js/**` 里那十几个文件**原样**按 manifest 顺序跑一遍,
然后直接调 `volStats` / `pressureLevels` / `simRun` 本尊。这条路是对的,但它有一个必须记住的怪癖。

**函数声明会挂到沙箱的 `globalThis` 上,顶层 `const` 不会。** `const` 落在 vm 全局的**词法**环境里,
Node 这一侧从 `ctx` 上读它,读到的是 `undefined` —— **不是抛错,是 `undefined`**。
所以脚本里有一行 bridge:装载完成后在沙箱**内部**再跑一句
`globalThis.PX = { PX_SIGMA_WIN, PX_REACH_C, … }`(`state` 和 `SIM_PRESETS` 同理),
把要用的词法绑定显式搭出来。规矩因此是一句话:**凡是 Node 侧要读的东西,必须出现在 bridge 那一行上,
否则它就是 `undefined`,而且没人会告诉你。**

漏掉一个的后果值得具体走一遍。假设 bridge 忘了带 `PX_HALF_U`:`0.35 * u` 变成 `undefined * u = NaN`,
带宽 NaN,bands 空,报告上印出来的是"这段历史画不出带",看起来像数据不够,不像常量丢了。
这种错误的特征是它**在每一层都合法**,所以只能用一个必炸的检查去挡:
装载末尾先 `if (!ctx.PX || !ctx.PX.PX_REACH_C) throw`,再对着名单逐个 `=== undefined` 抛,
错误话术直接写着"params.js 改了名,bridge 跟着改"。加常量、改常量名,这两处一起改。

同一处还有第二个机关,给 `tools/paramsearch.mjs` 用:既然沙箱外面既读不到也写不动那些 `const`,
唯一的注入点就是**脚本进沙箱之前改源码文本**。`overrideParamSrc()` 做这件事,
并且要求正则**命中且只命中一次**,命不中当场抛。这不是洁癖:一个静默失效的 override
会让整轮搜索变成"同一个配置跑了二十遍",而终端上每一行印的配置名都不一样 ——
出来的表格看着像一次搜索,事后完全分辨不出来。装载完成后还会从 bridge 出来的 `ctx.PX` 上
逐个回读实际值再对一遍,两道锁。磁盘上的 `params.js` 全程一个字节不动,
搜索进程崩在半路也不会留下一张被改过的参数表。

### 最少 K 根:两个下限**故意**不同,`INGEST_MIN_BARS`(13)< `BACKTEST_MIN_BARS`(40)

一份价格导出要有多少根才收得下来,浏览器摄取侧和回测读盘侧给的答案不一样,
而且**不许统一**。这两个数以前是分别写死在两个文件里的字面量(`px.length < 13` /
`px.length < 40`),于是"13 < 40"看上去像巧合;现在各自具名,不等式是被声明出来的:

| 常量 | 值 | 在哪 | 出处 | 谁消费 |
| --- | --- | --- | --- | --- |
| `INGEST_MIN_BARS` | 13 | `src/js/ingest/charting.js` | `volStats` 的 `ph.length < 13` / `rets.length < 12` | 面板(折线 / 蜡烛 / 波动率) |
| `BACKTEST_MIN_BARS` | 40 | `tools/backtest.mjs` 的 `loadDaily()` | 冻结常量 `PX_SIGMA_MIN_N = 40` | `sigmaD()` / `priceDensity()` |

13 是**能算出一个样本方差的最少点数**:13 个点 = 12 个收益率。摄取层比 `volStats` 更严没有收益,
更松则会收下一条 `volStats` 注定返回 `null` 的序列。这一侧还要吃周线 / 月线导出
(`volStats` 按日期中位间隔判频率,252 / 52 / 12 / 1 四档都支持)和新上市的短日线序列。

40 是 `PX_SIGMA_MIN_N`(SPEC 附录标注"不调"):回测只经 `sigmaD` 消费日线,不足 40 根收益
本来就出不了任何结论,在读盘处早筛掉比算到一半返回 `null` 干净。

**13–39 根这一段的差异今天就在真实数据上生效**:`Assets/charting/` 里 SPCX-US 只有 36 根(新上市),
所以面板显示 11 家公司,而 `loadDaily()` 只返回 10 只。统一到 40 会让 SPCX 从面板上静默消失;
统一到 13 会让回测拿 12 个收益率去估 σ。`tests/test-app.mjs` [16] 末尾三条行为断言
(12/13/39/40 四档夹具)加一条源码文本断言把这个差钉住 —— 谁要"顺手统一",先让它们变红。

两条还没做、但值得知道的事:

1. **`BACKTEST_MIN_BARS` 与 `PX_SIGMA_MIN_N` 靠注释对齐,不靠机器。** `loadDaily()` 不依赖
   `loadDashboard()`(读盘先于装载),而顶层 `const` 不挂沙箱 `globalThis`(见上一节),
   所以 Node 侧没法直接读到 `params.js` 里那个 40。改一处得记得改另一处。
   同理 `INGEST_MIN_BARS` **没有**加进 bridge 那一行 —— Node 侧不读它,桥出去只会让人
   误以为两边共用一个下限。
2. **`INGEST_MIN_BARS` 与 `volstats.js` 里的 13 也是两份字面量。** `volStats` 内部仍写着
   `ph.length < 13`。真要机械对齐,得让 `charting.js` 引用 `volstats.js` 的常量,
   而 manifest 里 `charting.js`(第 12)排在 `volstats.js`(第 21)前面 —— 只在函数体里用不会踩 TDZ,
   但这是一次跨模块求值顺序的改动,不属于"改个名"的范围。

### 回测台账:为什么记账,以及为什么不据此改权重

`--log` 把每轮的关键数字追加进 `Assets/_logs/backtest-history.csv`,菜单 `bt` 手动跑一轮,
抓取完成后若本自然月还没跑过则自动跑一轮(一次启动最多一回)。

三个设计点,都是为了几个月后这份文件还读得懂:

- **长表不是宽表。** 一行一个指标(`run_date,group,metric,horizon,n,effN,value,baseline,z,verdict`)。
  以后加一条腿只是多几行;宽表得改表头,几个月后的历史就对不上列了。
- **`verdict` 是受控词表**,共十个词。加词可以,改词不行——改了,几个月前那些行就跟今天的对不上。
  其中 `recorded` 表示"没有基准,只记数不判对错",`no_variance` 表示"这条腿整段历史是常数,
  一个字没说过"(和"看不出"完全两回事,后者该考虑摘掉)。
- **按自然月排期,不是"距上次满 30 天"。** 后者会让跑批日期每月往后漂几天,
  漂上半年就分不清"这轮是几月那一轮"了,而这份台账的全部用处就是回头对轮次。

**回测不会自动改任何权重。** 这不是谨慎,是算术:一年日线只有约 32 个不重叠的 21 日窗口,
看见红灯就调参,调的是这 32 个窗口的噪声,不是模型。报告可以自动出,手必须是人的。
真正值得回头翻这份台账的时刻只有一个——**某条腿的判语从"看不出"翻成了"反了"**。

依赖(`playwright` / `xlsx`)在根目录或 `fetcher/` 下装一份即可,测试两处都会找。

`tools/backtest.mjs` 里 **`xlsx` 不能写成 `import * as XLSX from 'xlsx'`**,原因值得记一笔:
ESM 的裸模块名是从**引用它的那个文件所在目录**逐级往上找 `node_modules` 的,跟进程 `cwd` 无关。
这个脚本在 `tools/`,而 `run-factset.bat` 首次启动是在 `fetcher/` 里 `npm i` 的——
于是"手动在根目录装过"的机器上一切正常,"只用 bat 装过"的机器上必崩 `ERR_MODULE_NOT_FOUND`,
而后者恰好是它被每月自动调起时的常态。改法是显式按三个锚点 `createRequire`
(本模块 → `fetcher/` → 仓库根),都没有就自己打一句人话并 `exit 3`;
调用方 `fetcher/lib/backtest.mjs` 认这个 3,把它翻成"跑一次 `npm i xlsx`",
而不是让 Node 把一整段堆栈糊到终端上。自检里钉了两条:静态裸导入不许回来,退出码 3 的约定两边要对得上。

## 前瞻台账:一份只能往后写的证据簿

`tools/ledger.mjs` 和 `tools/backtest.mjs` 长得像,干的是相反的事。回测是**反复重跑**的调参台,
台账是**只追加**的证据簿。它们分两个文件、两个 npm script,而且 `backtest.mjs` 里
搜不到 `ledger` / `forward-` 任何字样 —— 这不是代码洁癖,是防一件很容易发生的事:
同一个进程既能调参又能写台账,迟早有人跑完一轮调参顺手往台账里补一批"预测",
那批行和真预测长得一模一样,写完那一刻起就再也分不出来了。

四份 CSV 都在 `Assets/_logs/` 下:`forward-ledger.csv`(预测)、`forward-outcomes.csv`(结算)、
`engine-void.csv`(作废簿)、`param-adjudication.csv`(调参裁决簿)。全部只追加。
**本文件里没有回填函数,以后也不要加** —— 用今天的代码给昨天写预测,写出来的不是证据是拟合;
台账从第一次运行那天开始有意义,在此之前的空白就让它空着。

支撑这句话的是七道机制,每一道都对着一种具体的作弊手法:

`pred_id` 是**内容哈希**(`engine_ver|ticker|asof|horizon_d|claim|level_lo|level_hi` 的 sha256 前 16 位)。
同一天同一引擎版本重跑得到同一个 id,重复写入被拒。这是"不许回填"这句话的**执行**机制 ——
写在注释里的是愿望,内容哈希才是锁。

`engine_ver` 是引擎源文件拼接的 sha256 前 8 位,起**分区**作用。参数一动版本就换,
老预测和新预测永远不会被混进同一份统计。改一个常量再把新旧结果合起来算胜率,
是这类台账最常见的死法。

`resolve_after` 按 `asof` 往后数 `horizon_d` 个**交易日**,这一天之前不许结算。
防的是"提前收工":跌了就早两天结算,涨了就多等两天。同理还有停表规则 ——
`asof` 到 `resolve_after` 之间发生拆股/并股/停牌超过 3 日的,记 `stopped` 并**永久排除**,
不许顺延,顺延等于按结果挑窗口。

`features_sha` 在写入时刻把全部输入特征冻结成一个哈希。结算时重算对不上就标 `tainted`,
不许事后换一套新特征把旧预测算成对的。

`seal` 是"本行全部字段 + 上一行 seal"的 sha256 前 12 位,构成哈希链。
中间删一行、改一个数,后面全部对不上,`--verify` 会把断点指出来。

**作废簿**解决的是分区解决不了的那半个问题。分区只保证新旧不混统,不保证旧的那批本身干净。
这一轮就撞上了:`optionWalls()` 没按 `asof` 过滤期权行,重放时读到了几周后才被记录的未平仓量。
那一版引擎已经写下的 164 行预测,既不能删(删了哈希链就断,而且"删掉不利证据"本身
就是最该防的动作),也不能让它照常结算(结算出来的胜率是拿未来数据换的)。所以走第三条路:
**留着,盖戳,拒结** —— 给那个 `engine_ver` 在 `engine-void.csv` 里追加一行作废戳,
`--resolve` 从此拒绝结算它名下的任何行。作废簿自己也是只追加 + 哈希链,盖过的戳撤不掉。

**调参裁决簿**防的是"重搜"。一次搜索若只活在终端里,半年后没人分得清某个参数是
"测过、没效应"还是"根本没测过";于是下一个人再搜一遍,挑一个当时最好看的值,
并且真心以为自己是第一次搜。裁决留痕之后,重搜就得先解释上一次的结论错在哪。
它同样**不跑搜索** —— 数由 `tools/paramsearch.mjs` 出,这里只封签。

最后一条是读法:**同一个 `engine_ver` 分区内累积到 30 个独立事件,才第一次出判语**;
判语一旦是「反了」,那个 claim 在面板上立刻降级为 `falsified`。而且本工具**只打印判语,
不改 `src/` 里的任何一个字** —— 让代码根据自己的成绩单改自己,是另一类事故。

## 验收纪律:门槛先写,再跑

`tools/scratch/SPEC.md` 的 §3.9 是一张验收矩阵:每条腿 × 每个持有期一格,格子里写着通过门槛
(比如可达性 h=21 要求 OOS Brier skill > +0.15、LOO-CV 10 折下界 > 0、可靠性图 10 桶最大偏离 ≤ 0.10)。
表头上那句话是这套流程的全部要害:**门槛全部预注册于此,跑完回测再改这张表 = 作弊。**

为什么这句话需要被写下来,而不是靠自觉:调参和"改判据"在代码上是同一个动作 ——
都是编辑一个数字,都能让红灯变绿灯,而且事后从 diff 上分不出哪次是哪次。
唯一能分开它们的是**时间顺序**,所以顺序必须落成制度:先在 SPEC 里写死门槛和预期判语,
再跑。跑完之后 SPEC **只许追加**(比如追加一节记录这次搜索的过程和结论),
既有的阈值、预期判语、判据一个字都不许改。

配套的是兜底条款:任何一格判为「未过」,那条腿在面板上的 `evidence` 就落为 `pending`
或 `falsified`,**并且不得为了让它过而回头改参数**。这就是为什么
`src/js/pressure/params.js` 里的 `PX_EVIDENCE` 不是一个标签而是一个**渲染开关** ——
`reach` 是 `pending`,面板上就真的不显示触及概率。判语和界面之间不留人工环节,
是因为人工环节在下一轮压力下一定会被跳过。

允许的参数搜索也被同一张表限死:只有参数表里已经写明搜索范围的那三个
(`PX_SIGMA_WIN`、`PX_REACH_C`、`PX_HALFLIFE_D`),判据一律是 **LOO-CV 的样本外 Brier**,
不是命中率,不是 z。这一轮把三个都搜了,六格没有一格过线,于是三个值原样放回去 ——
一次什么都没搜到的搜索也是结论,它被写进了 `param-adjudication.csv`。

## 已知未修的缺陷

下面八条都是查出来、但**没有修**的东西(前六条来自调参那一轮,后两条来自 K 线面板那一轮)。
放在这里是因为它们各自都需要一次预注册或一次口径变更,不该顺手改掉;
也因为不写下来,下一个人会重新发现一遍。

**一、`PX_SIGMA_WIN = 20` 这一档根本跑不起来。** SPEC §3.3 给这个参数的搜索范围是
{20, 40, 60, 120},但同一份参数表里冻结着 `PX_SIGMA_MIN_N = 40`(少于 40 根收益不出结论),
20 根窗口永远喂不满,`sigmaD()` 一律返回 `null`。结果是 20 这一档在全部 5 档半衰期 ×
全部 3 个持有期上都是**零观测**,搜索表里那一行不是"输了",是"没参赛"。
两个后果:SPEC §3.3 的搜索范围和它自己冻结的常量互相矛盾;旧注释里
"60 根在三个 Brier 上都胜 20 根"这句话**在本仓库内无法验证** —— 它既没被证实也没被推翻。
要真的比,得先动 `PX_SIGMA_MIN_N`,而那是一次口径变更,得走预注册。

**二、ΔOI 在当前架构下拿不到。** `src/js/ingest/signals.js` 的 `ingestOptions`
(以及 `tools/ledger.mjs` 里的 `loadOptions`)在摄取阶段就按 `(到期日, 行权价)` 去重,
只留 `asof` 最新的那一条。也就是说历史快照在进入 `state.options` 之前就已经被丢掉了。
这带来一个很不直观的性质:本轮加的 as-of 前瞻护栏**只能丢行,不能找回正确的那一行** ——
它能拦住"读到未来的 OI",但拦住之后剩下的不是当时那条快照,而是什么都没有。
后果是所有依赖"同一个合约的 OI 变化"的想法(墙在长高还是在塌)都不成立,
不是没实现,是数据在两层之外就没了。要做得改摄取层的去重键,连带改 `state.options` 的形状。

**三、`[8]` 组有若干条断言写死了会过期的日期。** 夹具里用的到期日是
2026-08-14 / 08-21 / 09-18,而引擎按"今天往后 60 天窗口内、按 OI 选到期日"取合约。
2026 年 9 月中之后这些日子全部成为过去,那几条断言会集体转红,而**红的原因和被测的逻辑无关**。
应该改成相对今天算出来的日期(比如 today + 7 / +14 / +42)。没有当场改,是因为它
牵动 `[8]` 组好几处期望值,属于测试重构,不该和本轮的排版修一起提交。

**四、`[8]` 组那条"取两个证据等级里较弱的一个"的断言在它自己的夹具上是空转的。**
被测的逻辑是 `evidence: L.opts.length ? PX_EVIDENCE.opt : PX_EVIDENCE.reach`,
而那份夹具里**每一个价位都带期权腿**,于是三元的另一个分支从来没被走过。
断言现在是绿的,但它绿不绿和逻辑对不对没有关系。修法是往夹具里加一个纯技术轨的价位。

**五、SPEC §3.9 的兜底词表少一个词。** 条款只提供 `pending` 和 `falsified` 两种落法,
可 `bounce` 这一腿的实际状态两个都不是:它测了,z = −0.35 / −0.76,方向不支持,
但 effN 只有 17 / 16(要求 30),功率不足以判「反了」。这正是
`PX_EVIDENCE.bounce` 被写成 `inconclusive` 的原因 —— **代码里已经在用一个 SPEC 没定义的词**。
这个缺口得由下一轮预注册时给 §3.9 追加一条词表条目来补,不能反过来改代码去迁就一张不完整的表。

**六、TSM 的价格对不上。** 页面表头显示 402.9,期权那一步里用的是 374.67。
两个数出自不同的摄取路径,差 7.5%,尚未查清是快照日期不同、货币口径不同,还是某一侧取错了字段。
在查清之前,TSM 的期权轨结论不要单独引用。

**七、`setPriceHist()` 挑序列时不看有没有 OHLC。**

*症状*:同一只标的有两份价格序列时,K 线面板可能静默降级成收盘折线 —— 图还在,
只是从蜡烛变成了一条线,控制台干净,没有任何一处报错。

*触发条件*:`src/js/ingest/companies.js` 的打分是 `a.length * (hasVol(a) ? 1.5 : 1)`,
**只认长度和成交量,不认 O/H/L**。所以只要来了一份「252 点、有成交量、没有 OHLC」
和一份「比如 120 点、有成交量、带 OHLC」,前者得分 378、后者 180,选中的是**没有 OHLC 的那份**。
今天不会发生,因为盘上每只票都只有一份导出、且都没有 OHLC;
一旦 FactSet 那边把图切成 Candlestick 布局、而旧的收盘价导出还留在 `Assets/charting/` 里,
这两份就会同时存在 —— 那是这个缺陷第一次真的咬人的时刻,而它咬人的方式是"看起来一切正常"。

*为什么这次没修*:改打分函数会影响**现有全部标的**的序列选择结果,
而当前所有回测数字(A/C/D/E/F/G/H/I/J 各组)都是在现有选择结果上跑出来的。
为了一条今天不会执行的路径去动一个影响面覆盖全仓的函数,风险大于收益。
真要修,得把它当成一次口径变更:先想清楚"更长但没有 OHLC"和"更短但有 OHLC"到底谁更值钱
(这个问题没有唯一答案,取决于面板要画什么),再连带回归一遍全部回测数字。

**八、`tests/test-app.mjs` 里"渲染层不许出现指标"那条是关键词黑名单,不是语义检查。**

*症状*:这条断言绿着,但它证明不了"渲染层里算不出指标",只证明了
"渲染层的源码里没出现我列的那几个词"。

*触发条件*:断言是 `/\b(sma|ema|rsi|macd|macross|breakout|golden)/i` 对
`src/js/render/candles.js` 去掉注释后的源码做一次匹配。把函数名写成 `movingAvg`、
`trendLine`、`smooth20` 之类,一条指标线照画,断言照绿。
这条路已经被踩过一次:首版正则写成 `\bsma\b`,词尾那个 `\b` 正好漏掉 `sma20` / `rsi14`
这种带窗口长度的写法 —— 而那才是最可能出现的命名。变异测试因此**假绿**,
把词尾边界去掉之后才第一次报红。也就是说,这条断言的强度完全取决于词表列得全不全,
而词表是人手维护的。

*为什么这次没修*:真正的语义检查要么是"渲染层不许出现任何对历史序列的滑动窗口聚合"
(得做 AST 分析,这个仓库零依赖,不引 parser),要么是把 J 组那四个规范实现导出到
渲染层可见的地方再断言"渲染层没调过它们"(那要先有指标过闸,而 K.8 说 12 格全挂)。
两条路都不是这一轮该走的。在此之前,这条断言的正确读法是:
**它是一道提醒,不是一道证明。** 加指标的人只要不用这几个词就绕得过去,
所以真正的闸门仍然是 SPEC 附录 K.8 那句"一格没过就一条线都不许画",而不是这条正则。
